Computational simulation

What would happen in a system we cannot experiment on directly?

Encode mechanisms in a model (FEM, CFD, Monte Carlo, agent-based) and run experiments impossible, dangerous or too costly in reality.

How it works

  1. Model the system

    Describe the real system as a conceptual model (equations, rules, agents), then implement it as a program.

    “the computerized model is the conceptual model implemented on a computer.”

    Sargent (1987), p. 33

  2. Get the data right

    Check the data that feed the model: inputs, parameters and the measurements you will test it against.

    “Data validity is defined as ensuring that the data necessary for model building, model evaluation and testing, and conducting the model experiments to solve the problem are adequate and correct.”

    Sargent (1987), p. 33

  3. Verify the code

    Make sure the program does what the conceptual model says, with tests and known cases.

    “Model verification is frequently defined as ensuring that the computer program of the computerized model (i.e., the simulator) and its implementation is correct”

    Sargent (1987), p. 33

  4. Validate against reality

    Compare the model's output with the real system's behaviour, for the purpose and range you will use it for.

    “determining that the model’s output behavior has sufficient accuracy for its intended purpose or use over the domain of the model’s intended application.”

    Sargent (1987), p. 33, operational validity

  5. Run the experiments

    Run the scenarios many times with seeded random numbers, vary the inputs to see what drives the result, and report the simulation's own uncertainty.

    “This validation technique consists of changing the values of the input and internal parameters of a model to determine the effect upon the model and its output.”

    Sargent (1987), p. 34, sensitivity analysis

    “the Monte Carlo standard error (SE) as a measure of uncertainty due to using a finite number of simulation repetitions.”

    Morris, White & Crowther (2019), section 1 (introduction)

Where it breaks, and what protects it

  • Unvalidated model

    The model rests on assumptions nobody checked.

    Check the code is right, then check the model matches reality.

    “Model validation is usually defined to mean “substantiation that a computerized model within its domain of applicability possesses a satisfactory range of accuracy consistent with the intended application of the model””

    Sargent (1987), p. 33

  • Forking paths & p-hacking

    Try enough analyses and one of them will be 'significant'.

    Lock in the plan before you see the data.

A real example

Numerical-relativity waveforms of black-hole mergers, computed years before LIGO's first detection.

Defining reference: Sargent (2013). Verification and validation of simulation models. Journal of Simulation.
